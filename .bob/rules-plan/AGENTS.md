# AGENTS.md — Plan Mode

This file provides guidance to agents when working with code in this repository.

## Non-Obvious Architectural Constraints

- **IBM Bob is the only orchestrator.** No component (dashboard, MCP server, release engine) should independently trigger the workflow. All coordination flows through Bob.
- **The repo is a scaffold.** Most components have directory structure and empty files but no implementation. Plans must account for building from scratch, not extending existing logic.
- **MCP tools are stateless by architectural constraint**, not just convention. The caching and coordination layer Bob provides assumes this — stateful tools will break orchestration.
- **Two separate technology stacks exist side-by-side** with no shared build tooling: Node.js/TypeScript (`mcp-server/`) and Python (`release-engine/`). Plans that involve shared tooling must account for this split.
- **`sample-app/` intentional bugs are design fixtures**, not tech debt. Any plan to "fix" them must be scoped as a release-readiness demonstration exercise, not production hardening.
- **Release score thresholds are defined in the skill** (`.bob/skills/release-engineer/SKILL.md`), not in the scoring module. Any plan to implement `release-engine/src/scoring.py` must match those exact thresholds: 90–100 READY, 75–89 READY WITH WARNINGS, 50–74 NOT READY, 0–49 BLOCKED.
- **`reports/` output must be generated by Bob**, not pre-authored. Plans that pre-populate reports undermine the demonstrated workflow.
- **No root-level build/test runner.** Each component (`mcp-server/`, `release-engine/`, `sample-app/`, `dashboard/`) needs its own build/test setup. Plans must specify the component directory.
